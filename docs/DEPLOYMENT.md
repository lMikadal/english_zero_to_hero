# Deployment: ใช้แอปจริงบนเครื่องตัวเอง

แอปนี้ใช้คนเดียว รันบนเครื่อง Arch Linux ของเราเอง (Docker) แล้วเปิดจากมือถือผ่าน Tailscale ไม่ใช้ cloud
เอกสารนี้เขียนให้ทำตามได้ทีละขั้น: ช่อง "พิมพ์" คือคำสั่งที่ต้องพิมพ์ ช่อง "ควรเห็น" คือสิ่งที่ต้องเห็นถ้าถูกต้อง

## 1. ภาพรวม

```
มือถือ ──(Tailscale)──► เครื่องเรา 127.0.0.1:3100 ──► app (Next.js, production) ──► postgres 17
                                                         └─ ข้อมูลอยู่ใน Docker volume ezh_prod_pgdata
```

- **คนละชุดกับตอนพัฒนา:** ตอนพัฒนา (`make up`) ใช้ port 3000 และฐานข้อมูล `english_zero_to_hero_dev` ชุด production ใช้ project ชื่อ `ezh_prod`, port 3100, volume ของตัวเอง (`ezh_prod_pgdata`) และฐานข้อมูล `english_zero_to_hero` (ของจริง) เปิดพร้อมกันได้ ไม่ชนกัน และ `make db-reset` ใช้กับฐานข้อมูลจริงไม่ได้ (ยอมรับเฉพาะชื่อที่ลงท้าย `_dev`)
- **ทำไมแยกไฟล์ `docker-compose.prod.yml`:** ถ้าอยู่ไฟล์เดียวกับ dev จะใช้ postgres และ volume ตัวเดียวกัน ข้อมูลจริงกับข้อมูลทดลองจะปนกัน ไฟล์แยกบังคับให้ network, volume และชื่อ container แยกขาดจากกัน
- **Postgres ไม่เปิดออกนอก Docker เลย** (ไม่มี port บนเครื่อง) มีแต่แอปที่คุยกับมันได้ ส่วน backup ใช้ `docker exec`
- **บทเรียนอยู่ในตัว image** (โฟลเดอร์ `content/`): เมื่อมีบทใหม่หลัง `git pull` ต้อง `make prod-update`

> **กล่องความปลอดภัย (อ่านก่อนใช้)**
> - แอปนี้ **ไม่มีระบบ login**: ใครก็ตามที่เข้าถึง port ได้ จะเห็นและแก้ข้อมูลทั้งหมดได้
> - **เมื่อตั้ง `ALLOWED_IPS` (หัวข้อ 4.3.1): เฉพาะอุปกรณ์ที่ระบุเลข Tailscale ไว้** (กับเครื่องที่รันแอปเอง) ใช้แอปได้ อุปกรณ์อื่นใน tailnet เห็นแค่หน้า "อุปกรณ์นี้ไม่ได้รับอนุญาตให้ใช้แอป"
> - **ถ้าไม่ตั้ง `ALLOWED_IPS` (ว่าง): ทุกอุปกรณ์และทุกคนใน tailnet ใช้แอปได้** ถ้าแชร์เครื่องหรือเชิญคนอื่นเข้า tailnet เขาจะเห็นข้อมูลเรา (`make prod-up` และ `make prod-status` เตือนเมื่อว่าง)
> - `ALLOWED_IPS` เป็นการจำกัดว่า "เครื่องไหนเข้าได้" ไม่ใช่ login: ใครที่ใช้เครื่องที่ได้รับอนุญาต (หรือนั่งหน้าเครื่องที่รันแอป) เข้าได้เสมอ
> - **ห้ามสั่ง `tailscale funnel`** (เปิดสู่อินเทอร์เน็ตสาธารณะ) และ **ห้ามตั้ง `APP_BIND=0.0.0.0`** เด็ดขาด
>
> **สองแอปในเครื่องเดียว:** port **3000** = แอปตอนพัฒนา ข้อมูลทดลอง (`make up`) ลบ/รีเซ็ตได้ ส่วน port **3100** = แอปจริง ข้อมูลจริงของเรา อย่าสับสนกัน (ยังไม่มีป้ายบอกบนหน้าจอ ดูหัวข้อ 8)

### ศัพท์ที่จะเจอ

- **image:** "แม่พิมพ์" ของแอป ที่ได้จากการ build (`make prod-build`) มีโค้ดและบทเรียนอยู่ข้างใน แก้ไม่ได้ ต้อง build ใหม่เมื่อมีเวอร์ชันใหม่
- **container:** แอปหรือฐานข้อมูลที่กำลังรันจริง สร้างจาก image ลบทิ้งแล้วสร้างใหม่ได้โดยข้อมูลไม่หาย
- **volume:** ที่เก็บ **ข้อมูลจริงของเรา** (ความคืบหน้า, คะแนน, การ์ดทวน) ชื่อ `ezh_prod_pgdata` **ห้ามลบ** ถ้าหายคือข้อมูลหายหมด (กู้ได้จากไฟล์ backup เท่านั้น)
- **migration:** ชุดคำสั่งที่ปรับโครงสร้างตารางในฐานข้อมูลให้ตรงกับแอปเวอร์ชันใหม่ รันอัตโนมัติก่อนแอปเริ่ม
- **tailnet:** เครือข่ายส่วนตัวของ Tailscale ที่มีเฉพาะอุปกรณ์ของเรา (เครื่องนี้และมือถือ)

## 2. ติดตั้งครั้งแรก

ต้องมี Docker กับ git บนเครื่อง (มีอยู่แล้ว) เปิด Docker ก่อน แล้วเข้าโฟลเดอร์โปรเจกต์

```bash
docker-on
cd ~/Documents/english_zero_to_hero
git checkout main && git pull
make prod
```

`make prod` ทำ 3 อย่างต่อกัน: สร้างไฟล์ `.env.prod` พร้อมรหัสผ่านฐานข้อมูลสุ่ม (ถ้ายังไม่มี) → build image → เริ่มระบบ (รัน migration ให้เองก่อนเริ่มแอป)
ครั้งแรกใช้เวลาหลายนาที (โหลดแพ็กเกจ) ถ้าเน็ตช้าอาจนานกว่านี้ ปล่อยให้ทำงานจนจบ

**ควรเห็น** บรรทัดสุดท้าย `production is up: http://127.0.0.1:3100`

ตรวจว่าใช้ได้:

```bash
make prod-status
```

**ควรเห็น** `app-1 ... (healthy)`, `postgres-1 ... (healthy)`, `migrate-1 Exited (0)` (ปกติ: มันทำงานครั้งเดียวแล้วจบ) และบรรทัด `{"ok":true} <- /api/health`
จากนั้นเปิดเบราว์เซอร์บนเครื่อง ไปที่ `http://127.0.0.1:3100` ควรเห็นหน้าแรก "English Zero to Hero"

> `make prod-init` **ไม่เขียนทับ** `.env.prod` ที่มีอยู่แล้ว
> ไฟล์ `.env.prod` มีรหัสผ่านฐานข้อมูล ห้าม commit (git ละเว้นให้อยู่แล้ว) ถ้าลบไฟล์นี้หลังสร้างฐานข้อมูลแล้ว รหัสใหม่จะเข้าฐานข้อมูลเดิมไม่ได้ ให้เก็บไฟล์นี้ไว้ (ใส่ใน backup ของไฟล์ส่วนตัวด้วย)
> `make prod-up` จะไม่ยอมเริ่มถ้ารหัสผ่านยังเป็นค่าตัวอย่างหรือสั้นเกินไป

## 3. เปิด–ปิดทุกวัน

Docker **ไม่ได้เปิดเองตอนบูต** เราเปิดเอง

```bash
# เริ่มใช้
docker-on
sudo systemctl start tailscaled   # ถ้าไม่ได้ตั้งให้ Tailscale เปิดเองตอนบูต (หัวข้อ 4.1) ต้องสั่งทุกครั้งหลังเปิดเครื่อง ไม่งั้นมือถือเข้าไม่ได้
make prod-up      # ถ้าตอนปิดครั้งก่อนไม่ได้สั่ง make prod-down และไม่ได้ลบ container จะไม่ต้องสั่ง (ดูข้างล่าง)

# เลิกใช้
make prod-down    # หยุดแอป (ข้อมูลยังอยู่ใน volume)
docker-off
```

- **ถ้าปิด Docker (`docker-off`) โดยไม่ได้สั่ง `make prod-down`:** ครั้งหน้าที่ `docker-on` แอปและฐานข้อมูลจะกลับมารันเอง (ตั้ง `restart: unless-stopped`) เพราะ container เหล่านี้ยังอยู่ในสถานะ "กำลังรัน" ตอน Docker หยุด นี่ **ไม่ใช่การเปิดตอนบูต**: Docker เองไม่ได้ตั้งให้เปิดตอนบูต จึงไม่มีอะไรเริ่มเองจนกว่าเราจะสั่ง `docker-on`
- **ถ้าสั่ง `make prod-down`:** container ถูกลบ ต้องสั่ง `make prod-up` เองครั้งหน้า (เร็ว ไม่ต้อง build ใหม่)
- ทั้งสองแบบ **ข้อมูลไม่หาย** เพราะอยู่ใน volume `ezh_prod_pgdata` (`make prod-down` ไม่ลบ volume ห้ามเติม `-v`)
- ตอนเครื่องหรือ Docker ปิด มือถือเปิดแอปไม่ได้ (ยังไม่มี PWA ออฟไลน์ ดูหัวข้อ 8)

## 4. เปิดจากมือถือ (Tailscale) — **ขั้นตอนนี้คุณเป็นคนทำเอง**

ผมไม่ได้รันคำสั่งเหล่านี้ให้ (ต้อง sudo และต้อง login บัญชีของคุณ) และยังไม่เคยลองเปิดจากมือถือจริง

### 4.1 ติดตั้ง Tailscale บนเครื่อง

```bash
sudo pacman -S tailscale
sudo systemctl start tailscaled      # เริ่มครั้งนี้เท่านั้น ไม่เปิดตอนบูต
sudo tailscale up                    # จะพิมพ์ลิงก์ให้เปิดเพื่อ login
```

(ถ้าอยากให้ Tailscale เปิดเองตอนบูต ใช้ `sudo systemctl enable --now tailscaled` แทน: นี่คือบริการของ Tailscale ไม่เกี่ยวกับ Docker; เลือกเอง)

### 4.2 มือถือ

ติดตั้งแอป Tailscale แล้ว login ด้วยบัญชีเดียวกับเครื่อง จากนั้นเปิด https://login.tailscale.com/admin/dns เปิด **MagicDNS** และ **HTTPS Certificates**

### 4.3 วิธีที่เลือกใช้: HTTPS ด้วย `tailscale serve`

> ตัดสินใจแล้ว (2026-11-28): ใช้ HTTPS ผ่าน `tailscale serve` เป็นทางหลัก ฟรีบนแผนส่วนตัว และจำเป็นสำหรับติดตั้งลงหน้าจอโฮม ใช้ออฟไลน์ และไมโครโฟน

```bash
sudo tailscale serve --bg 3100
sudo tailscale serve status   # แสดงที่อยู่ https://<ชื่อเครื่อง>.<tailnet>.ts.net (บางเครื่องไม่ใช้ sudo ก็ได้ ถ้าขึ้นว่าไม่มีสิทธิ์ให้ใส่ sudo)
```

**หลังสั่ง `sudo tailscale serve --bg 3100` ควรเห็น** ที่อยู่แบบ `https://<ชื่อเครื่อง>.<tailnet>.ts.net` ถ้ามันพิมพ์ลิงก์ให้ไปเปิดใช้ Serve/HTTPS ของ tailnet ให้เปิดลิงก์นั้น กดเปิดใช้ แล้วสั่งคำสั่งเดิมอีกครั้ง (ข้อความที่เห็นอาจต่างเล็กน้อยตามรุ่น: ผมยังไม่ได้ลองบนเครื่องจริง)

เปิดที่อยู่นั้นบนมือถือ ใช้งานได้เฉพาะอุปกรณ์ในบัญชี Tailscale ของเรา ไม่เปิดสู่อินเทอร์เน็ตสาธารณะ ไม่ต้องแก้ router
(ตั้งไว้แล้วจะจำข้ามการรีสตาร์ท: ถ้าเครื่องเปิดแต่ Docker ปิด หน้าจะขึ้น error จนกว่าจะ `docker-on`; เลิกใช้ด้วย `sudo tailscale serve reset`)

ลำดับที่ถูกต้องทั้งหมด: เปิดแอป (`make prod-up`) → **ตั้ง `ALLOWED_IPS` ตามหัวข้อ 4.3.1 ข้อ 1–4 ก่อน** (หาเลขมือถือด้วย `tailscale status` ได้โดยไม่ต้องเปิด serve) → `sudo tailscale serve --bg 3100` → เปิดบนมือถือ

อย่าเพิ่งสั่ง `tailscale serve` ถ้ายังไม่ได้ตั้ง `ALLOWED_IPS` (ข้างล่างเป็นคำสั่ง serve แต่ให้ทำ 4.3.1 ข้อ 1–4 ก่อน) เพื่อไม่ให้มีช่วงที่ทุกอุปกรณ์ใน tailnet เข้าได้

### 4.3.1 จำกัดว่าอุปกรณ์ไหนใช้แอปได้ (`ALLOWED_IPS`)

แอปนี้ไม่มีรหัสผ่าน จึงมี "รายชื่ออุปกรณ์ที่อนุญาต" โดยดูจากเลข Tailscale (`100.x.y.z`) ของแต่ละเครื่อง ตั้งไว้ในบรรทัด `ALLOWED_IPS=` ของ `.env.prod` ถ้าว่าง = ทุกอุปกรณ์ใน tailnet ใช้ได้ (เหมือนก่อนมีฟีเจอร์นี้)

ทำตามลำดับ (หลังสั่ง `tailscale serve` ในหัวข้อ 4.3):

1. **หาเลขของมือถือ:** บนเครื่องที่รันแอป พิมพ์ `tailscale status` จะเห็นรายการเครื่องทั้งหมด คอลัมน์แรกคือเลข `100.x.y.z` คอลัมน์ถัดมาคือชื่อเครื่อง (หาชื่อมือถือของคุณ) หรือเปิดแอป Tailscale บนมือถือ แล้วดูเลขใต้ชื่อเครื่องตัวเอง มือถือมีเลข Tailscale สองแบบ: 100.x.y.z และเลขยาวที่ขึ้นต้น fd7a:115c:a1e0: (ดูในแอป Tailscale บนมือถือ) ใส่ทั้งสองเลขใน ALLOWED_IPS คั่นด้วยจุลภาค ถ้ามือถือเห็นหน้าปฏิเสธพร้อมเลขที่ขึ้นต้น fd7a: ให้เพิ่มเลขนั้น
2. **ใส่ใน `.env.prod`:** เปิดไฟล์ แก้บรรทัด `ALLOWED_IPS=` เช่น `ALLOWED_IPS=100.101.102.103` (หลายเครื่องคั่นด้วยจุลภาค: `ALLOWED_IPS=100.101.102.103, 100.88.5.7`) ใส่ช่วงเลขแบบ `100.64.0.0/10` ได้ แต่นั่นเท่ากับอนุญาตทุกเครื่องของ Tailscale จึงไม่แนะนำ ห้ามใส่พอร์ต ชื่อเครื่อง หรือ `*`
3. **ใช้ค่าใหม่:** พิมพ์ `make prod-up` (ถ้าพิมพ์รูปแบบผิด คำสั่งจะหยุดก่อนเริ่มและบอกว่ารายการไหนผิด แอปที่รันอยู่ไม่ถูกแตะ)
4. **ตรวจ:** พิมพ์ `make prod-status` **ควรเห็น** `access: only these devices ...` และบรรทัดสุดท้าย `access ok: the allow-list is enforced` ถ้าเห็น `access FAIL` อย่าเพิ่งเปิดบนมือถือ ส่งข้อความนั้นให้ผม
5. **ตั้ง `tailscale serve`** ตามหัวข้อ 4.3 (`sudo tailscale serve --bg 3100`) ถ้ายังไม่ได้ตั้ง
6. **เปิดบนมือถือ**

**เพิ่ม/ลบเครื่อง:** แก้รายการใน `ALLOWED_IPS` แล้ว `make prod-up` อีกครั้ง (ข้อมูลไม่หาย)

**ถ้าเครื่องไม่ได้รับอนุญาต** จะเห็นหน้า "อุปกรณ์นี้ไม่ได้รับอนุญาตให้ใช้แอป" (HTTP 403) พร้อมเลข IP ที่แอปเห็น ถ้าเป็นเครื่องของเราเอง ให้คัดลอกเลขนั้นไปใส่ใน `ALLOWED_IPS` ตามข้อ 2–3 หน้านี้ไม่แสดงข้อมูลอื่นเลย

**ถ้าล็อกตัวเองออก:** เครื่องที่รันแอปเข้าได้เสมอที่ `http://127.0.0.1:3100` โดยไม่ต้องอยู่ในรายการ เปิดเบราว์เซอร์บนเครื่องนั้น แก้ `.env.prod` แล้ว `make prod-up` แอปไม่มีทางล็อกเครื่องที่รันมันเอง

**ทำไมเครื่องอื่นปลอมตัวไม่ได้:** แอปเชื่อเลข IP ที่ `tailscale serve` ส่งมา เฉพาะเมื่อคำขอมาจากเครื่องนี้เองหรือจาก gateway ของเครือข่าย Docker ชุดนี้เท่านั้น (เครือข่ายของ production มีวงเลขเฉพาะ `172.30.10.0/24`) container อื่น (รวมถึง postgres) ที่ส่ง header ปลอมมาจะถูกตัดสินด้วยเลขของตัวเอง และถูกปฏิเสธ `make prod-status` ทดสอบข้อนี้ให้ทุกครั้ง (บรรทัด `another container forging ... was refused`)

**ข้อสมมติที่ต้องรู้ (พูดตรงๆ):** ทั้งหมดนี้พึ่งว่า `tailscale serve` ใส่เลขของเครื่องที่เรียกมาให้ (ตรวจจากซอร์สโค้ดของ Tailscale แล้ว แต่ยังไม่เคยตรวจกับมือถือจริงของคุณ) ถ้าวันหนึ่ง serve ใส่ header อื่นแต่ไม่ใส่เลข แอปจะปฏิเสธ (หน้าขึ้น "ไม่ทราบ") ไม่ปล่อยผ่านเป็นเครื่องนี้เอง ดังนั้นการพิสูจน์จริงคือเช็กลิสต์ด้านล่าง **ทำซ้ำทุกครั้งหลังอัปเดต Tailscale**

**ข้อจำกัดที่ควรรู้:**
- รายการนี้จำกัด "อุปกรณ์" ไม่ใช่ "คน": ใครถือเครื่องที่อยู่ในรายการก็ใช้ได้
- ทุกโปรแกรมที่รันบนคอมพิวเตอร์เครื่องนี้ถือเป็นเครื่องนี้ (เข้าได้เสมอ)
- เลข Tailscale ของอุปกรณ์อาจเปลี่ยนถ้าลบอุปกรณ์ออกจากบัญชีแล้วเพิ่มใหม่ ต้องแก้รายการตาม
- ถ้า `ALLOWED_IPS` ว่าง ทุกอุปกรณ์ใน tailnet ใช้ได้
- ใช้ได้เฉพาะ `APP_BIND=127.0.0.1` กับ `tailscale serve` (`make prod-up` ปฏิเสธการตั้งค่าอื่น)

**ชั้นที่สอง (ไม่บังคับ): การควบคุมการเข้าถึงของ Tailscale เอง** — ในหน้า admin ของ Tailscale มีระบบกำหนดว่าอุปกรณ์ไหนในบัญชีเข้าถึงเครื่องไหนได้ (access controls) ใช้เสริมได้ เพื่อให้ตัวเครือข่ายเองก็กันเครื่องที่ไม่ต้องการ **ผมยังไม่ได้ตรวจเรื่องนี้ในที่นี้** (ไม่มี Tailscale ให้ลอง) และไม่ขอระบุชื่อเมนูหรือรูปแบบไฟล์ ให้ดูเอกสารทางการของ Tailscale ว่าด้วย access controls ตอนจะตั้ง `ALLOWED_IPS` ทำงานได้โดยไม่ต้องพึ่งข้อนี้

#### ตรวจครั้งแรกกับมือถือจริง (ยังไม่เคยตรวจ: ไม่มี Tailscale ในที่ที่ผมทำงาน)

สิ่งเดียวที่ผมพิสูจน์ไม่ได้คือ `tailscale serve` ส่งเลขของมือถือมาให้แอปถูกต้องหรือไม่ (ตรวจแล้วเฉพาะจากซอร์สโค้ดของ Tailscale ที่ระบุว่าตั้ง `X-Forwarded-For` เป็นเลขของเครื่องที่เรียก) ตรวจครั้งแรกด้วยตัวเอง:

- [ ] ตั้ง `ALLOWED_IPS` เป็นเลขของ**เครื่องอื่น** (หรือเลขสมมติ เช่น `100.64.0.1`) โดย **ไม่ใส่เลขของมือถือ** แล้ว `make prod-up`
- [ ] เปิดแอปบนมือถือผ่านที่อยู่ `https://<ชื่อเครื่อง>.<tailnet>.ts.net` **ต้องเห็นหน้า "อุปกรณ์นี้ไม่ได้รับอนุญาตให้ใช้แอป"** และเลข IP บนหน้านั้นต้องตรงกับเลข Tailscale ของมือถือ (ดูใน `tailscale status`)
- [ ] **ถ้าเลขบนหน้านั้นไม่ใช่เลขของมือถือ หรือมือถือเข้าแอปได้ทั้งที่ไม่ได้อยู่ในรายการ: ปิดการเข้าจากมือถือทันทีด้วย `sudo tailscale serve reset` แล้วส่งผลให้ผม (แปลว่าการจำกัดอุปกรณ์ใช้ไม่ได้กับเครื่องนี้)**
- [ ] ใส่เลขมือถือที่เห็นบนหน้านั้นลงใน `ALLOWED_IPS`, `make prod-up`, รีเฟรชบนมือถือ ต้องเข้าแอปได้
- [ ] เอาเลขมือถือออกอีกครั้ง `make prod-up` ต้องกลับไปเห็นหน้าปฏิเสธ (ยืนยันว่าการลบมีผล) แล้วใส่กลับ

### 4.4 ทางสำรอง (ไม่ใช่ทางหลัก): HTTP ธรรมดาผ่าน Tailscale

ใช้เฉพาะถ้า HTTPS ตั้งไม่ได้ชั่วคราว ฟีเจอร์ PWA/ออฟไลน์/ไมโครโฟนจะใช้ไม่ได้ในแบบนี้ (ดูตารางข้างล่าง)

```bash
tailscale ip -4               # ได้เลขแบบ 100.x.y.z
```

แก้ `.env.prod` ให้ `APP_BIND=100.x.y.z` แล้ว `make prod-down && make prod-up` เปิด `http://100.x.y.z:3100` บนมือถือ
**ใช้ร่วมกับ `ALLOWED_IPS` ไม่ได้ (เครื่องอื่นจะถูกมองว่าเป็นเครื่องนี้เอง)** `make prod-up` จะปฏิเสธถ้าตั้งทั้งสองอย่าง
ข้อควรรู้: Docker ต้องเริ่มหลัง Tailscale ขึ้นแล้ว ไม่งั้น container แอปจะเปิด port ไม่ได้ (ถ้าเป็นแบบนี้ ให้ `sudo tailscale up` แล้ว `make prod-up` อีกครั้ง)

| | HTTPS (4.3 ทางหลัก) | HTTP (4.4 ทางสำรอง) |
|---|---|---|
| เรียนบทเรียน, บันทึกผล, ทวนคำศัพท์ | ได้ | ได้ |
| ติดตั้งเป็นแอป (PWA), service worker/ออฟไลน์ | ได้ (เมื่อฟีเจอร์เสร็จ) | **ไม่ได้** (เบราว์เซอร์ต้องการ HTTPS) |
| ไมโครโฟน (ฝึกพูด/อัดเสียง) | ได้ (เมื่อฟีเจอร์เสร็จ) | **ไม่ได้** |

การเข้ารหัสระหว่างมือถือกับเครื่องมีอยู่แล้วในทั้งสองแบบ (Tailscale เข้ารหัสทั้งเส้นทาง) ต่างกันที่เบราว์เซอร์ถือว่า HTTP เป็นหน้า "ไม่ปลอดภัย" และปิดฟีเจอร์บางอย่าง ทางหลักที่เลือกไว้คือ HTTPS (4.3)

## 5. อัปเดตเป็นเวอร์ชันใหม่

```bash
cd ~/Documents/english_zero_to_hero
git pull
make prod-update
```

`make prod-update` ทำตามลำดับ: **backup ข้อมูลปัจจุบันก่อน** (ไฟล์ลงท้าย `-pre-update.dump`; ถ้า backup ไม่สำเร็จ การอัปเดตหยุดทันที) → build image ใหม่ (รวมบทเรียนใหม่) → เริ่มด้วยเวอร์ชันใหม่ โดยรัน migration ก่อนแอปเริ่ม (ครั้งแรกที่ติดตั้งยังไม่มีข้อมูล จึงไม่ต้อง backup)

- ถ้าเผลอสั่งแค่ `make prod-up` (ไม่ผ่าน `prod-update`): ระบบเทียบรายการ migration ในตัว image กับฐานข้อมูล ถ้ามี migration ใหม่ที่ยังไม่เคยรัน จะ backup (`-pre-update`) ให้เองก่อน
- Migration รันซ้ำได้และทำเฉพาะที่ยังไม่เคยทำ ไฟล์ migration ที่มีคำสั่งลบข้อมูล (`DROP TABLE`, `DROP COLUMN`, `TRUNCATE`, เปลี่ยนชนิดคอลัมน์) จะผ่าน CI ได้ก็ต่อเมื่อมีคนตรวจแล้วเขียน `-- destructive: reviewed` ไว้ในไฟล์ ถ้า migration ล้มเหลว แอปใหม่จะไม่เริ่ม ดูสาเหตุด้วย `make prod-logs`
- อยากรัน migration เองโดยไม่เปลี่ยนแอป: `make prod-migrate`
- image พื้นฐาน (node, postgres) ใช้แท็กที่ขยับได้: อัปเดตย่อยของมันเข้ามาเองเมื่อ build ใหม่ (ตั้งใจ เพื่อรับแพตช์ความปลอดภัย)
- ครั้งแรกหลังอัปเดตเป็นเวอร์ชันที่มี `ALLOWED_IPS` จะเห็นข้อความ `network ezh_prod_default uses …; moving it to 172.30.10.0/24`: container ถูกสร้างใหม่ครั้งเดียว ข้อมูลไม่หาย (ย้ายตอนเริ่มแอปใหม่หลัง backup และ build จึงไม่เพิ่มเวลาที่แอปดับ) ถ้าระบบแจ้งว่าเครือข่ายชนกัน (`the subnet … overlaps the docker network …`) แอปจะยังทำงานต่อด้วยเครือข่ายเดิมและไม่มีอะไรถูกหยุด (`make prod-update` ตรวจเรื่องนี้ก่อน backup): ส่งข้อความนั้นให้ผม
- ถ้าอัปเดตแล้วมีปัญหา: restore จากไฟล์ `-pre-update` (หัวข้อ 6)

## 6. Backup และ restore

```bash
make prod-backup
```

**ควรเห็น** ชื่อไฟล์ เช่น `backups/ezh-english_zero_to_hero-20261127-230734.dump` ไฟล์เป็น `pg_dump` แบบบีบอัด เก็บในโฟลเดอร์ `backups/` (git ละเว้น) เจ้าของคือเรา ไม่ใช่ root เก็บล่าสุด 14 ไฟล์ (แก้ได้ด้วย `BACKUP_KEEP` ใน `.env.prod` ต้องเป็นเลขเต็มตั้งแต่ 1 ขึ้นไป) ไฟล์ `-pre-update` นับแยก เก็บ 5 ไฟล์ล่าสุด ไฟล์ `-pre-restore` **ไม่ถูกลบอัตโนมัติเลย** (อาจเป็นสำเนาเดียวของข้อมูลล่าสุดก่อน restore ลบเองเมื่อแน่ใจแล้ว) ชื่อไฟล์ใช้เวลา UTC และ backup ใหม่จะไม่ถูกลบโดย backup ของมันเอง โฟลเดอร์ `backups/` เป็นสิทธิ์ 700 และไฟล์ 600 เพราะมีข้อมูลผู้เรียนทั้งหมด

ระบบ **ยังไม่ backup อัตโนมัติ** (ไม่ได้ตั้ง cron/systemd เพราะไม่แตะเครื่องเรา) แนะนำให้สั่ง `make prod-backup` ก่อน `make prod-down` ทุกครั้ง หรือถ้าอยากให้อัตโนมัติ บอกผมได้ จะเขียนวิธีตั้ง systemd timer ให้คุณรันเอง

**เอา backup ออกจากเครื่อง** (กันฮาร์ดดิสก์เสีย) เช่นคัดลอกไป USB หรือเครื่องอื่น:

```bash
cp backups/ezh-english_zero_to_hero-*.dump /run/media/$USER/<ชื่อ USB>/
# หรือไปอีกเครื่องใน Tailscale:
scp backups/ezh-english_zero_to_hero-*.dump <ผู้ใช้>@<เครื่องอื่น>:~/ezh-backups/
```

**Restore** (แทนที่ข้อมูลทั้งหมดในฐานข้อมูลจริงด้วยข้อมูลในไฟล์):

```bash
ls backups/
make prod-restore FILE=backups/ezh-english_zero_to_hero-20261127-230734.dump CONFIRM=english_zero_to_hero
```

ขั้นตอนอัตโนมัติ: ตรวจว่าไฟล์ใช้ได้ (เป็นของฐานข้อมูลนี้ ไม่ใหม่กว่าแอปเวอร์ชันนี้) → หยุดแอป → **backup ข้อมูลปัจจุบันไว้ก่อน** (`-pre-restore.dump`, ไม่ลบ backup ใดๆ รวมถึงไฟล์ที่กำลัง restore) → ล้างตารางของแอปแล้วโหลดไฟล์ในธุรกรรมเดียว (ล้มกลางทาง = ข้อมูลเดิมไม่เปลี่ยน; ตารางที่มีแต่ในเวอร์ชันใหม่จะไม่หลงเหลือ) → เริ่มระบบด้วยเส้นทางปกติ (รัน migration แล้วเปิดแอป) ถ้าไม่พิมพ์ `CONFIRM=` ให้ตรงชื่อฐานข้อมูล คำสั่งจะปฏิเสธ

คำสั่งจะปฏิเสธ (พร้อมข้อความไทย/อังกฤษ) เมื่อ: ไฟล์เป็นของฐานข้อมูลอื่น (ชื่อต้องขึ้นต้น `ezh-<ชื่อฐานข้อมูล>-` และข้อมูลในไฟล์ต้องมาจากฐานข้อมูลเดียวกัน; ถ้าแน่ใจจริงใส่ `ALLOW_OTHER_DB=1`) หรือไฟล์มาจากแอปเวอร์ชันที่ใหม่กว่า (ให้อัปเดตแอปก่อน; ถ้าแน่ใจใส่ `ALLOW_NEWER=1`)

**ตรวจว่า backup กู้คืนได้จริง** (ไม่แตะข้อมูลจริง: restore ลงฐานข้อมูลชั่วคราวในคอนเทนเนอร์ postgres, นับจำนวนแถว แล้วลบทิ้ง):

```bash
make prod-backup-verify FILE=backups/ezh-english_zero_to_hero-20261127-230734.dump
```

**ควรเห็น** `backup OK (restorable)` ควรทำเป็นครั้งคราว เพราะ backup ที่กู้ไม่ได้ก็เท่ากับไม่มี backup

### ย้ายไปเครื่องใหม่

ลำดับสำคัญ: รหัสผ่านฐานข้อมูลถูกกำหนดตอนสร้างฐานข้อมูลครั้งแรก ถ้า `make prod` สร้าง `.env.prod` ใหม่ก่อน แล้วค่อยก๊อปไฟล์เก่าทับ รหัสจะไม่ตรงกับฐานข้อมูลและเข้าไม่ได้

เครื่องใหม่ที่ clone มาจะ **ไม่มีโฟลเดอร์ `backups/`** ต้องสร้างเอง

1. `docker-on` แล้ว `git clone <ที่อยู่ repo> ~/Documents/english_zero_to_hero && cd ~/Documents/english_zero_to_hero` **ยังไม่สั่ง `make prod`**
2. คัดลอกไฟล์ `.env.prod` เก่ามาไว้ในโฟลเดอร์โปรเจกต์ **ก่อน** (หรือข้ามขั้นนี้ก็ได้: ระบบจะสุ่มรหัสผ่านใหม่ และ restore ก็ยังใช้ได้)
3. `mkdir -p backups` แล้วคัดลอกไฟล์ `.dump` เข้าไป **โดยไม่เปลี่ยนชื่อ** (ชื่อต้องขึ้นต้น `ezh-english_zero_to_hero-`)
4. `make prod` (ได้ระบบเปล่า) แล้ว `make prod-restore FILE=backups/<ไฟล์> CONFIRM=english_zero_to_hero`
5. `make prod-status` ต้องเห็น `(healthy)` แล้วเปิดแอป ตรวจว่าข้อมูลของเรากลับมา

เนื้อหาบทเรียนอยู่ใน git อยู่แล้ว ไม่ต้อง backup แยก

## 7. ถ้ามีอะไรผิดปกติ

| อาการ | ทำอะไร |
|---|---|
| เปิดแอปไม่ได้ | `make prod-status` ดูว่า app เป็น `healthy` ไหม; ถ้าไม่มี container เลย แสดงว่าลืม `docker-on` หรือ `make prod-up` |

| แอปเริ่มไม่ขึ้นหลังอัปเดต | `make prod-logs` ดู 100 บรรทัดล่าสุด; ส่งข้อความ error ให้ผม |
| port 3100 ถูกใช้อยู่ | แก้ `APP_PORT` ใน `.env.prod` แล้ว `make prod-up` (และ `tailscale serve` ให้ตรงกัน) |
| มือถือเปิดแอปไม่ได้ แต่บนเครื่องเปิดได้ | `sudo systemctl start tailscaled` แล้ว `tailscale status` ต้องเห็นมือถือในรายการ; `sudo tailscale serve status` ต้องเห็นที่อยู่ https://... |
| มือถือเห็นหน้า "อุปกรณ์นี้ไม่ได้รับอนุญาตให้ใช้แอป" | คัดลอกเลข IP ที่แสดงบนหน้านั้นไปใส่ใน `ALLOWED_IPS` ใน `.env.prod` แล้ว `make prod-up` (หัวข้อ 4.3.1) ถ้าเลขนั้นไม่ตรงกับเลขของมือถือใน `tailscale status` ให้หยุดและส่งให้ผม |
| ทุกหน้าตอบ 500 หลังแก้ `ALLOWED_IPS` | ปกติ `make prod-up` จะหยุดก่อนถ้าพิมพ์ผิด แต่ถ้าเกิดขึ้น: `make prod-logs` แล้วหาคำว่า `invalid entry` จะบอกว่ารายการไหนผิด แก้แล้ว `make prod-up` |
| `make prod-status` ขึ้น `access FAIL` | อ่านบรรทัดที่ขึ้นต้น `access FAIL` (บอกว่าข้อไหนไม่ผ่าน: เครื่องเองถูกปฏิเสธ / เลขที่ไม่อยู่ในรายการเข้าได้ / header ปลอมถูกเชื่อ) ส่งให้ผม อย่าเปิดบนมือถือจนกว่าจะ `access ok` |
| ข้อมูลเพี้ยน | `make prod-restore` จาก backup ล่าสุด (หัวข้อ 6) |

### พื้นที่ดิสก์เต็ม

เมื่อ build หลายครั้ง image เก่าจะสะสม ล้างได้อย่างปลอดภัย (ไม่แตะข้อมูล):

```bash
docker image prune        # ลบ image ที่ไม่มีใครใช้
docker builder prune      # ลบ cache ของการ build
```

> **อันตราย ห้ามสั่งเด็ดขาด:** `docker volume prune -a` (หรือ `--all`), `docker system prune -a --volumes`, `docker volume rm ...` และ `docker compose ... down -v`
> คำสั่งเหล่านี้ลบ volume ข้อมูลจริง `ezh_prod_pgdata` ได้ ตอนที่แอปหยุดอยู่ (เช่นหลัง `make prod-down`) ข้อมูลทั้งหมดจะหายถาวร กู้คืนไม่ได้
> ก่อนล้างอะไรที่ไม่แน่ใจ ให้ `make prod-backup` แล้วคัดลอกไฟล์ออกจากเครื่องก่อน

### ลองของโดยไม่แตะข้อมูลจริง (stage)

ชุดทดลองใช้ image ของตัวเอง (`ezh-stage-app`) และโฟลเดอร์ `backups-stage/` ของตัวเอง จึงไม่ทับ image ของแอปจริงและไม่แตะ `backups/`
ชุดทดลองที่แยกขาด (project `ezh_stage`, ฐานข้อมูล `english_zero_to_hero_stage`, port 3190): `make stage-init`, `make stage-build`, `make stage-up`, `make stage-status`, `make stage-backup`, `make stage-restore FILE=... CONFIRM=english_zero_to_hero_stage`, `make stage-update`, และ `make stage-down` (ลบชุดทดลองพร้อม volume ของมันเท่านั้น) ไม่มีคำสั่ง make ใดที่ลบ volume ของ production

## 8. สิ่งที่ยังไม่ได้ทำ / ยังไม่ได้ตรวจ

- **PWA** (ติดตั้งลงหน้าจอโฮม, ใช้ออฟไลน์): ยังไม่ได้ทำ ตอนนี้ต้องเปิดเครื่องและ Docker ถึงจะใช้ได้ ตามที่เขียนใน [PLAN.md](PLAN.md)
- **เสียงต้นฉบับ (audio)** และการอัดเสียง: ยังไม่ได้ทำ
- **HTTPS:** ยังไม่ได้ตั้ง ต้องตั้งเองด้วยหัวข้อ 4.3 (ต้องมีเพื่อ PWA/ไมโครโฟน)
- **Backup อัตโนมัติรายวัน:** ยังไม่ได้ตั้ง (สั่งเองด้วย `make prod-backup`)
- **ยังไม่เคยตรวจจากมือถือจริงผ่าน Tailscale** (ตรวจแล้วเฉพาะบนเครื่อง ด้วย `curl` และ stack ทดลอง ดู [FEATURE_MAP.md](FEATURE_MAP.md) หัวข้อ "ตรวจ production stack")
- **ผู้ใช้คนเดียว:** ยังไม่มีระบบ login; จำกัดด้วย `ALLOWED_IPS` (หัวข้อ 4.3.1: ว่าง = ทุกอุปกรณ์ใน Tailscale ของเรา) อย่าเปิด port 3100 สู่อินเทอร์เน็ต (อย่าตั้ง `APP_BIND=0.0.0.0`)
- **`ALLOWED_IPS` กับ `tailscale serve` จริง:** ยังไม่เคยตรวจจากมือถือจริง (เช็กลิสต์ท้ายหัวข้อ 4.3.1); ตรวจแล้วกับ stack ทดลองโดยจำลอง `X-Forwarded-For` ด้วย curl
- **ป้ายบอกว่าเป็นแอปทดลอง:** ยังไม่มีป้ายบนหน้าจอที่แยก port 3000 (ทดลอง) กับ 3100 (จริง) ทำเป็นงานต่อไป
- การแจ้งเตือน (push) และฟีเจอร์ AI: ยังไม่มี
