# Progress: การคำนวณพัฒนาการของผู้เรียน

แอปคำนวณพัฒนาการ 3 เรื่อง จากผลการฝึกที่บันทึกไว้ทุกครั้ง

1. **คำศัพท์ที่รู้จริง**
2. **จุดอ่อนที่ต้องแก้**
3. **ระดับ CEFR โดยประมาณ และการเรียนตามแผน 365 วัน**

หลักการ:
- **เก็บข้อมูลดิบตั้งแต่วันแรก** (Milestone 1) และแสดงผลเต็มรูปแบบทีหลัง (Milestone 2) ประวัติจึงครบตั้งแต่บทเรียนแรก
- **คำนวณจากข้อมูลดิบทุกครั้ง** ไม่เก็บผลสรุปซ้ำในฐานข้อมูล เพราะผู้ใช้คนเดียวมีข้อมูลประมาณ 25,000 แถวต่อปี ซึ่งคำนวณสดได้ทัน และแก้สูตรทีหลังได้โดยไม่ต้องแก้ข้อมูลเก่า
- **สูตรเป็นฟังก์ชันล้วน** อยู่ใน `src/lib/progress/` รับข้อมูลเข้า คืนผลออก ไม่แตะฐานข้อมูล จึงเขียนเทสต์ก่อนได้ทุกสูตรตามแนว TDD
- ตัวเลขเกณฑ์ทั้งหมดในเอกสารนี้เป็นค่าคงที่ใน `src/lib/progress/config.ts` ปรับได้ที่เดียว

## 1. ข้อมูลดิบที่ต้องเก็บ

| ตาราง | ข้อมูลที่ใช้ | บันทึกเมื่อ |
|---|---|---|
| `attempts` | `day`, `skill`, `exercise_type`, `correct`, `score`, `duration_ms`, `tags` | ผู้เรียนตอบแบบฝึกหัด 1 ข้อ |
| `srs_reviews` | `vocab_id`, `direction`, `rating`, `reviewed_at`, สถานะการ์ดก่อนและหลัง | ทบทวนคำศัพท์ 1 ครั้ง |
| `srs_cards` | `stability`, `state`, `lapses`, `due` | สถานะล่าสุดของการ์ดแต่ละใบ |
| `recordings` | `pron_score` (คะแนนรายเสียงย่อย) | ส่งเสียงให้ระบบให้คะแนน |
| `progress` | `status`, `score`, `completed_at` | เริ่มและจบบทเรียน |
| `profiles` | `start_date`, `current_day` | ตั้งค่าครั้งแรก และเมื่อจบบท |

`attempts.tags` คือรายการสิ่งที่แบบฝึกหัดข้อนั้นฝึก เช่น `phoneme:ae`, `vocab:v-cat` หน้าเล่นบทเรียนเป็นคนเติมจากไฟล์บทเรียน ใช้หาจุดอ่อนรายเสียงและรายคำ

## 2. คำศัพท์ที่รู้จริง

แต่ละคำอยู่ใน 4 สถานะ โดยดูจากการ์ดทบทวนของคำนั้น

| สถานะ | เงื่อนไข |
|---|---|
| ยังไม่เรียน | ยังไม่มีการ์ดของคำนี้ |
| กำลังเรียน | มีการ์ดแล้ว แต่ยังไม่ถึงเกณฑ์ "จำได้" |
| จำได้ | การ์ดทิศ `en_th` (เห็นคำอังกฤษ บอกความหมาย) มี `stability` ≥ 7 วัน |
| **รู้จริง** | การ์ดทั้งทิศ `en_th` และ `th_en` (เห็นความหมาย นึกคำอังกฤษ) มี `stability` ≥ 21 วัน และการทบทวนครั้งล่าสุดของทั้งสองทิศตอบถูก |

`stability` คือค่าที่ระบบทบทวน (FSRS) ประเมินว่าเราจะจำคำนี้ได้อีกกี่วัน คำที่ "รู้จริง" จึงหมายถึงคำที่คาดว่าจำได้เกิน 3 สัปดาห์โดยไม่ต้องทวน และนึกออกได้ทั้งสองทาง

ตัวเลขที่แสดง:
- **จำนวนคำแต่ละสถานะ** รวม และแยกตามระดับ Oxford (A1, A2, B1, B2)
- **ความคืบหน้า Oxford 3000:** คำที่รู้จริง / 3,000
- **อัตราการจำได้:** จำนวนครั้งที่ตอบถูก / จำนวนครั้งที่ทบทวน ของการ์ดที่ผ่านขั้นเรียนใหม่แล้ว ในช่วง 30 วันล่าสุด (เป้าหมายประมาณ 90%)
- **คำที่ลืมบ่อย:** การ์ดที่ `lapses` ≥ 3

## 3. จุดอ่อนที่ต้องแก้

หาจาก 4 มุม ในช่วง **14 วันล่าสุด**

| มุม | จัดกลุ่มตาม | ข้อมูล |
|---|---|---|
| เสียง | `phoneme:*` ใน `attempts.tags` และคะแนนรายเสียงใน `recordings.pron_score` | เสียงที่ออกผิดหรือฟังแยกไม่ออก |
| คำศัพท์ | `vocab_id` | คำที่ลืมบ่อย (`lapses` สูง หรือตอบผิดซ้ำ) |
| ประเภทแบบฝึกหัด | `exercise_type` | เช่น เขียนตามคำบอกผิดบ่อย |
| ทักษะ | `skill` | ทักษะที่คะแนนต่ำสุดใน 5 ทักษะ |

สูตรของแต่ละกลุ่ม:

```
อัตราผิด = ผลรวมน้ำหนักของข้อที่ผิด / ผลรวมน้ำหนักของทุกข้อ
น้ำหนักของแต่ละข้อ = 0.5 ^ (จำนวนวันที่ผ่านมา / 7)     ← ข้อที่เพิ่งทำมีน้ำหนักมากกว่า
```

- นับเฉพาะกลุ่มที่มีอย่างน้อย **5 ข้อ** ในช่วงเวลา เพื่อไม่ให้ผิด 1 จาก 1 ข้อกลายเป็นจุดอ่อน
- เป็นจุดอ่อนเมื่ออัตราผิด ≥ **30%**
- แสดงสูงสุด **5 อันดับ** ต่อมุม เรียงจากอัตราผิดมากไปน้อย
- จุดอ่อน "หาย" เมื่ออัตราผิดลดต่ำกว่า 15%

**ฝึกเฉพาะจุดอ่อน:** ปุ่มนี้สร้างชุดฝึกสั้น 5–10 นาที โดยดึงแบบฝึกหัดจากบทเรียนที่เรียนแล้วซึ่งมี tag ตรงกับจุดอ่อนอันดับต้น และดึงการ์ดของคำที่ลืมบ่อยมาทวน

## 4. ระดับ CEFR โดยประมาณ

ระดับที่แสดงคือ **ระดับสูงสุดที่ผ่านครบทั้งสองเงื่อนไข**

| ระดับ | สอบวัดผลที่ต้องผ่าน (คะแนน ≥ 70%) | คำที่รู้จริงขั้นต่ำ |
|---|---|---|
| Pre-A1 | (เริ่มต้น) | 0 |
| A1 | วันที่ 60 (จบเฟส 1) | 400 |
| A2 | วันที่ 150 (จบเฟส 2) | 1,200 |
| B1 | วันที่ 270 (จบเฟส 3) | 1,850 |
| B2 | วันที่ 360 (สอบครั้งสุดท้าย) | 2,400 |

- จำนวนคำขั้นต่ำคิดจาก 80% ของคำสะสมตามแผนในแต่ละเฟส (500 / 1,500 / 2,300 / 3,000)
- แสดงความคืบหน้าไประดับถัดไปเป็นเปอร์เซ็นต์ โดยใช้ค่าที่น้อยกว่าระหว่างความคืบหน้าของคำศัพท์กับความคืบหน้าของบทเรียน
- ในแอปต้องเขียนกำกับว่าเป็น **"ระดับโดยประมาณ"** เพราะคำนวณจากผลในแอป ไม่ใช่ผลสอบมาตรฐาน

## 5. เรียนตามแผน 365 วัน

```
วันที่ควรอยู่   = จำนวนวันนับจาก start_date + 1        (ไม่เกิน 365)
วันที่เรียนถึง  = จำนวนบทเรียนที่สถานะ done
ช้ากว่าแผน     = วันที่ควรอยู่ − วันที่เรียนถึง − 1     (บทของวันนี้ยังไม่นับว่าช้า)
ความเร็ว       = จำนวนบทที่จบใน 14 วันล่าสุด / 14       (บทต่อวัน)
วันที่คาดว่าจบ  = วันนี้ + (365 − วันที่เรียนถึง) / ความเร็ว
```

| สถานะ | เงื่อนไข |
|---|---|
| ทันแผน | ช้ากว่าแผน ≤ 0 วัน |
| ช้าเล็กน้อย | ช้า 1–3 วัน |
| ช้ากว่าแผน | ช้า 4 วันขึ้นไป และแสดงจำนวนวันกับวันที่คาดว่าจะจบ |

- ถ้าความเร็วเป็น 0 (ไม่ได้เรียนเลยใน 14 วัน) ให้แสดงว่า "ยังคำนวณวันจบไม่ได้" แทนการหารด้วยศูนย์
- วันที่ใช้เขตเวลาใน `profiles.timezone`
- ตัวเลขอื่นที่แสดงคู่กัน: streak ปัจจุบันและสูงสุด, เวลาฝึกรวมต่อสัปดาห์ (จาก `duration_ms`)

## 6. แผนการทำ

| ช่วง | สิ่งที่ทำ |
|---|---|
| Milestone 0 (PR ฐานข้อมูล) | ตารางและคอลัมน์ตามหัวข้อ 1 |
| Milestone 1 | หน้าเล่นบทเรียนบันทึก `attempts` ครบทุกช่องรวม `tags`; ระบบทบทวนบันทึก `srs_reviews`; สูตรใน `src/lib/progress/` พร้อมเทสต์; หน้าสรุปสั้นหลังจบบท (คำใหม่วันนี้, คำที่รู้จริงสะสม, ทันแผนหรือไม่) |
| Milestone 2 | หน้า "พัฒนาการ" เต็มรูปแบบ: คำศัพท์แยกระดับ, รายการจุดอ่อน, ระดับ CEFR, กราฟย้อนหลัง, ปุ่มฝึกเฉพาะจุดอ่อน |

## 7. สิ่งที่ยังไม่ได้ออกแบบ

- **คะแนนรายทักษะย้อนหลังเป็นกราฟ:** ข้อมูลดิบพอสำหรับทำได้ แต่ยังไม่อยู่ในขอบเขตที่เลือกไว้
- **tag ของแบบฝึกหัดในไฟล์บทเรียน:** ตอนนี้หน้าเล่นบทเรียนต้องอนุมาน tag เอง (จาก `phoneme_intro` ของบทนั้นและ `vocabId`) ถ้าไม่แม่นพอ ต้องเพิ่มช่อง `focus` ใน `docs/CONTENT_SCHEMA.md`
- **เกณฑ์ทั้งหมด** (7 วัน, 21 วัน, 30%, 70%, จำนวนคำต่อระดับ) เป็นค่าตั้งต้นจากการประมาณ ต้องปรับหลังมีข้อมูลการเรียนจริง
