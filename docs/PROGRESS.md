# Progress: การคำนวณพัฒนาการของผู้เรียน

แอปคำนวณพัฒนาการ 3 เรื่อง จากผลการฝึกที่บันทึกไว้ทุกครั้ง

1. **คำศัพท์ที่รู้จริง**
2. **จุดอ่อนที่ต้องแก้**
3. **ระดับ CEFR โดยประมาณ และการเรียนตามแผน 365 วัน**

หลักการ:
- **เก็บข้อมูลดิบตั้งแต่วันแรก** (Milestone 1) และแสดงผลเต็มรูปแบบทีหลัง (Milestone 2) ประวัติจึงครบตั้งแต่บทเรียนแรก
- **คำนวณจากข้อมูลดิบทุกครั้ง** ไม่เก็บผลสรุปซ้ำในฐานข้อมูล เพราะผู้ใช้คนเดียวมีข้อมูลประมาณ 25,000 แถวต่อปี ซึ่งคำนวณสดได้ทัน และแก้สูตรทีหลังได้โดยไม่ต้องแก้ข้อมูลเก่า
- **สูตรเป็นฟังก์ชันล้วน** อยู่ใน `src/lib/progress/` รับข้อมูลเข้า คืนผลออก ไม่แตะฐานข้อมูล จึงเขียนเทสต์ก่อนได้ทุกสูตรตามแนว TDD
- ตัวเลขเกณฑ์ทั้งหมดในเอกสารนี้เป็นค่าคงที่ใน `src/lib/progress/config.ts` ปรับได้ที่เดียว

## 1. ข้อมูลดิบที่ต้องเก็บ

| ตาราง | ข้อมูลที่ใช้ | บันทึกเมื่อ |
|---|---|---|
| `attempts` | `day`, `skill`, `exercise_type`, `correct`, `score`, `duration_ms`, `tags`, `source`, `session_id`, `attempt_no` | ผู้เรียนตอบแบบฝึกหัด 1 ข้อ |
| `srs_reviews` | `vocab_id`, `direction`, `rating`, `reviewed_at`, สถานะการ์ดก่อนและหลัง | ทบทวนคำศัพท์ 1 ครั้ง |
| `srs_cards` | `stability`, `state`, `lapses`, `due` | สถานะล่าสุดของการ์ดแต่ละใบ |
| `recordings` | `pron_score` (คะแนนรายเสียงย่อย) | ส่งเสียงให้ระบบให้คะแนน |
| `progress` | `status`, `score`, `completed_at` | เริ่มและจบบทเรียน |
| `profiles` | `start_date`, `current_day` | ตั้งค่าครั้งแรก และเมื่อจบบท |

`attempts.tags` คือรายการสิ่งที่แบบฝึกหัดข้อนั้นฝึก เช่น `phoneme:ae`, `vocab:v-cat` หน้าเล่นบทเรียนเป็นคนเติมจากไฟล์บทเรียน ใช้หาจุดอ่อนรายเสียงและรายคำ

`attempts.attempt_no` คือครั้งที่ตอบ: 1 = ตอบครั้งแรก, 2 = ตอบซ้ำรอบท้ายบท (บทเรียนถามข้อที่ตอบผิดซ้ำอีกหนึ่งครั้งตอนจบบท) และ `score` เป็นสัดส่วน 0–1 เสมอ (1 = 100%) ส่วนข้อที่ระบบตรวจให้ไม่ได้ (พูดแล้วประเมินตัวเอง `repeat_after_me`, `shadowing`, `speak_answer` และ `free_write`) เก็บ `score` เป็น null และ `correct` เป็นเพียงการประเมินตัวเอง/การนับจำนวนคำ

กติกาที่ใช้กับสูตรพัฒนาการ:
1. **ครั้งแรกเท่านั้น:** อัตราผิดและคะแนนทุกอย่างใช้เฉพาะข้อที่ `attempt_no = 1` (ข้อตอบซ้ำไม่นับ ไม่เช่นนั้นการตอบซ้ำจะบังที่ผิดไว้) บท drill/retest ไม่มีรอบตอบซ้ำจึงไม่กระทบ
2. **ข้อที่ไม่มีคะแนนไม่นับ:** ข้อที่ `score` เป็น null ไม่นับในการหาจุดอ่อนทั้ง 4 มุม รวมถึงเกณฑ์ขั้นต่ำ 5 ข้อ
3. **ตอบถูกบางส่วน:** ข้อผิดคือ `1 − score` (ไม่ใช่ `correct` แบบถูก/ผิดทั้งหมด) เช่น ได้ 0.7 นับเป็นผิด 0.3

ข้อใน `drill` และ `retest` ต้องมี tag ระบุจุดอ่อนที่เป็นเป้าหมาย รูปแบบ `weakness:<มุม>:<ชื่อ>` เช่น `weakness:phoneme:ae`, `weakness:vocab:v-cat`, `weakness:skill:listening`, `weakness:exerciseType:dictation` สร้างและอ่านด้วย `weaknessTag()` / `parseWeaknessTag()` ใน `src/lib/progress/weakness.ts` (หน้าเล่นบทฝึกต้องใช้ฟังก์ชันเดียวกัน) tag นี้ไม่นับเป็นกลุ่มเสียงหรือคำศัพท์ในการหาจุดอ่อน

`attempts.source` บอกว่าข้อนั้นมาจากไหน: `lesson` (บทเรียนรายวัน), `drill` (บทฝึกจุดอ่อน), `retest` (บททดสอบจุดอ่อน) `checkpoint` (สอบวัดผลรายเดือน) หรือ `practice` (เล่นบทที่เรียนจบแล้วซ้ำ ไม่แตะ `progress`) ส่วน `session_id` ใช้รวมข้อที่ทำในรอบเดียวกัน

## 2. คำศัพท์ที่รู้จริง

แต่ละคำอยู่ใน 4 สถานะ โดยดูจากการ์ดทบทวนของคำนั้น

| สถานะ | เงื่อนไข |
|---|---|
| ยังไม่เรียน | ยังไม่มีการ์ดของคำนี้ |
| กำลังเรียน | มีการ์ดแล้ว แต่ยังไม่ถึงเกณฑ์ "จำได้" |
| จำได้ | การ์ดทิศ `en_th` (เห็นคำอังกฤษ บอกความหมาย) มี `stability` ≥ 7 วัน |
| **รู้จริง** | การ์ดทั้งทิศ `en_th` และ `th_en` (เห็นความหมาย นึกคำอังกฤษ) มี `stability` ≥ 21 วัน และการทบทวนครั้งล่าสุดของทั้งสองทิศตอบถูก |

การตีความที่ใช้ในโค้ด:
- "มีการ์ดแล้ว" คือมีแถวใน `srs_cards` อย่างน้อยหนึ่งทิศ (ไม่ว่า `state` ใด)
- "ตอบถูก" คือ `rating` ≥ 2 (Hard, Good, Easy); `rating` 1 (Again) คือตอบผิด
- "ผ่านขั้นเรียนใหม่แล้ว" คือ `state` ก่อนทบทวน (ใน `srs_reviews.state_before`) เป็น 2 (Review) หรือ 3 (Relearning)
- ช่วง 30 วันนับจากเวลาปัจจุบันย้อนหลัง 30×24 ชั่วโมง รวมขอบ ถ้าไม่มีการทบทวนที่เข้าเกณฑ์เลย อัตราการจำได้เป็น "ไม่มีข้อมูล" (ไม่ใช่ 0%)
- ความคืบหน้า Oxford 3000 นับคำที่ "รู้จริง" ในรายการ 3000 หารด้วย 3,000 คงที่
- คำที่ลืมบ่อย: ใช้ `lapses` สูงสุดของการ์ดทุกทิศของคำนั้น
- อัตราการจำได้นับการทบทวนทุกทิศ (`en_th`, `th_en`, `listen_spell`, `speak`)
- การทบทวนที่เวลาเดียวกันพอดีของทิศเดียวกัน: ถ้ามีข้อผิดอยู่ด้วยถือว่าครั้งล่าสุดผิด (ไม่ขึ้นกับลำดับในข้อมูล)
- รูปแบบ `srs_reviews.state_before` / `state_after` (jsonb) ที่สูตรอ่าน: ออบเจ็กต์ที่มีฟิลด์การ์ดของ ts-fsrs (`due`, `stability`, `difficulty`, `elapsed_days`, `scheduled_days`, `reps`, `lapses`, `state`, `last_review`) โดย `state` เป็นตัวเลข 0 New, 1 Learning, 2 Review, 3 Relearning สูตรอ่านเฉพาะ `state_before.state` ถ้าไม่มีหรือไม่ใช่ตัวเลข การทบทวนนั้นไม่นับ ระบบทบทวนต้องบันทึกรูปแบบนี้

`stability` คือค่าที่ระบบทบทวน (FSRS) ประเมินว่าเราจะจำคำนี้ได้อีกกี่วัน คำที่ "รู้จริง" จึงหมายถึงคำที่คาดว่าจำได้เกิน 3 สัปดาห์โดยไม่ต้องทวน และนึกออกได้ทั้งสองทาง

ตัวเลขที่แสดง:
- **จำนวนคำแต่ละสถานะ** รวม และแยกตามระดับ Oxford (A1, A2, B1, B2)
- **ความคืบหน้า Oxford 3000:** คำที่รู้จริง / 3,000
- **อัตราการจำได้:** จำนวนครั้งที่ตอบถูก / จำนวนครั้งที่ทบทวน ของการ์ดที่ผ่านขั้นเรียนใหม่แล้ว ในช่วง 30 วันล่าสุด (เป้าหมายประมาณ 90%)
- **คำที่ลืมบ่อย:** การ์ดที่ `lapses` ≥ 3

## 3. จุดอ่อนที่ต้องแก้

หาจาก 4 มุม ในช่วง **14 วันล่าสุด**

| มุม | จัดกลุ่มตาม | ข้อมูล |
|---|---|---|
| เสียง | `phoneme:*` ใน `attempts.tags` และคะแนนรายเสียงใน `recordings.pron_score` | เสียงที่ออกผิดหรือฟังแยกไม่ออก |
| คำศัพท์ | tag `vocab:<id>` ใน `attempts.tags` | คำที่ลืมบ่อย (`lapses` สูง หรือตอบผิดซ้ำ) |
| ประเภทแบบฝึกหัด | `exercise_type` | เช่น เขียนตามคำบอกผิดบ่อย |
| ทักษะ | `skill` | ทักษะที่คะแนนต่ำสุดใน 6 ทักษะ (pronunciation, listening, speaking, reading, writing, vocabulary) |

สูตรของแต่ละกลุ่ม:

```
อัตราผิด = ผลรวม (น้ำหนัก × (1 − score)) / ผลรวมน้ำหนักของทุกข้อ
น้ำหนักของแต่ละข้อ = 0.5 ^ (จำนวนวันที่ผ่านมา / 7)     ← ข้อที่เพิ่งทำมีน้ำหนักมากกว่า
```

- ข้อที่นับ: `attempts` ที่ `source` เป็น `lesson` หรือ `checkpoint`, `attempt_no = 1` และ `score` ไม่เป็น null เท่านั้น ข้อจาก `drill`, `retest` และ `practice` ไม่นับ เพื่อไม่ให้การฝึกซ้ำทำให้จุดอ่อนดูหายไปหรือแย่ลงเกินจริง
- ช่วง 14 วันนับย้อนหลังจากเวลาปัจจุบัน (อายุข้อเป็นวันแบบเศษส่วน) รวมขอบ และไม่นับข้อที่เวลาอยู่ในอนาคต
- แต่ละข้อนับเข้ากลุ่มของทุก tag `phoneme:*` และ `vocab:*` ของข้อนั้น รวมถึงกลุ่ม `exercise_type` และ `skill` ของข้อนั้น (กลุ่มคำศัพท์จัดตาม tag `vocab:<id>`)
- เส้นคะแนนเสียงจาก `recordings.pron_score` ยังไม่นับในสูตรนี้ (รอ PR ที่เก็บคะแนนรายเสียง)
- นับเฉพาะกลุ่มที่มีอย่างน้อย **5 ข้อ** ในช่วงเวลา (นับข้อดิบ ไม่ถ่วงน้ำหนัก) เพื่อไม่ให้ผิด 1 จาก 1 ข้อกลายเป็นจุดอ่อน
- เป็นจุดอ่อนเมื่ออัตราผิด ≥ **30%**
- แสดงสูงสุด **5 อันดับ** ต่อมุม เรียงจากอัตราผิดมากไปน้อย
- จุดอ่อน "หาย" เมื่ออัตราผิดลดต่ำกว่า 15% (ต้องมีอย่างน้อย 5 ข้อเช่นกัน) ช่วง 15–30% ไม่ใช่ทั้งจุดอ่อนและหาย
- อันดับที่เท่ากัน เรียงตามชื่อกลุ่ม (ตัวอักษรจากน้อยไปมาก) เพื่อให้ผลคงที่

**รายการจุดอ่อนที่แสดงในแอป** ใช้ฟังก์ชันเดียวคือ `weakPoints()` (ไม่ใช่ `detectWeaknesses` ซึ่งเป็นฟังก์ชันระดับล่าง) กติกา:
- แสดงกลุ่มเมื่อเป็นจุดอ่อนอยู่ตอนนี้ (อัตราผิด ≥ 30% และมี ≥ 5 ข้อ) **หรือ** มีวงจรฝึกที่ยังเปิดอยู่ (สถานะ กำลังแก้ / รอทดสอบซ้ำ) และยังไม่หาย (อัตราผิดยัง ≥ 15% หรือมีน้อยกว่า 5 ข้อ)
- เลิกแสดงเมื่อสถานะเป็น "แก้ได้แล้ว" หรือหายเอง (< 15% และ ≥ 5 ข้อ) กรณีหายเอง ถือว่าวงจรที่เปิดอยู่ปิดแล้ว และสถานะกลับเป็น "ยังไม่เริ่ม"
- หลังแก้ได้แล้ว อัตราผิดคำนวณจากข้อ `lesson`/`checkpoint` ที่ทำหลังเวลาที่แก้ได้แล้วเท่านั้น (จึงไม่ขัดกับสถานะ)
- เรียงตามมุม (เสียง, คำ, ประเภท, ทักษะ) แล้วตามอัตราผิดมากไปน้อย สูงสุด 5 อันดับต่อมุม

เมื่อพบจุดอ่อน แอปจะเปิด **บทพัฒนาจุดอ่อน** ของจุดนั้นให้ทำ (ดูหัวข้อ 3.1)

### 3.1 บทพัฒนาจุดอ่อน

จุดอ่อนแต่ละจุดมีบทของตัวเอง ทำเป็นวงจร **ฝึก → ทดสอบ → ติดตามผล**

```
พบจุดอ่อน ──► บทฝึก (drill) ──► บททดสอบ (retest) ──► ผ่าน? ──► ทดสอบซ้ำอีกวัน ──► แก้ได้แล้ว
                  ▲                                     │ ไม่ผ่าน
                  └─────────────────────────────────────┘
```

| ขั้น | เนื้อหา | เวลา |
|---|---|---|
| **บทฝึก** | คำอธิบายสั้นเป็นภาษาไทยว่าผิดตรงไหนและแก้อย่างไร ตามด้วยแบบฝึกหัด 8–12 ข้อ เรียงจากง่ายไปยาก เฉลยและคำอธิบายขึ้นทันทีหลังตอบ | 5–8 นาที |
| **บททดสอบ** | 8 ข้อที่**ไม่ซ้ำ**กับบทฝึก ไม่มีคำใบ้ระหว่างทำ สรุปคะแนนตอนจบ พร้อมเทียบกับคะแนนก่อนฝึก | 3–5 นาที |

เกณฑ์:
- **ผ่านบททดสอบ** เมื่อได้ ≥ 80% (ตอบถูกอย่างน้อย 7 จาก 8 ข้อ)
- **จุดอ่อนถือว่าแก้ได้แล้ว** เมื่อผ่านบททดสอบ **2 ครั้งในคนละวัน** เพื่อยืนยันว่าจำได้จริง ไม่ใช่เพิ่งฝึกมาเมื่อกี้
- ถ้าไม่ผ่าน แอปให้ทำบทฝึกอีกรอบด้วยข้อชุดใหม่ และสุ่มบททดสอบชุดใหม่
- จุดอ่อนที่แก้ได้แล้วจะกลับมาอีก ถ้าอัตราผิดในบทเรียนปกติกลับขึ้นถึง 30%
- ในหนึ่งวันแอปแนะนำบทพัฒนาจุดอ่อน **ไม่เกิน 2 จุด** เพื่อไม่ให้แย่งเวลาบทเรียนประจำวัน

ที่มาของข้อในบทฝึกและบททดสอบ:

| มุมของจุดอ่อน | ที่มาของข้อ |
|---|---|
| เสียง | คลังบทฝึกที่เขียนไว้ล่วงหน้า 1 ไฟล์ต่อ 1 เสียง ใน `content/drills/` เช่น `phoneme-th.json` (คู่คำเสียงใกล้กัน, ฟังแล้วเลือก, พูดตาม) ครอบคลุมเสียงที่คนไทยมักผิดตาม [CURRICULUM.md](CURRICULUM.md) |
| คำศัพท์ | สร้างอัตโนมัติจากคลังคำศัพท์: จับคู่ความหมาย, ฟังแล้วสะกด, แต่งประโยค โดยใช้คำที่ลืมบ่อยของผู้เรียนคนนั้น |
| ประเภทแบบฝึกหัด | ดึงข้อประเภทนั้นจากบทเรียนที่เรียนไปแล้ว โดยเลือกข้อที่เคยผิดและข้อที่ไม่ได้ทำมานานก่อน |
| ทักษะ | ผสมข้อของทักษะนั้นจากบทเรียน 14 วันล่าสุด |

แต่ละไฟล์ใน `content/drills/` ต้องมีข้ออย่างน้อย **24 ข้อ** (ฝึก 2 รอบ รอบละ 8 ข้อ + ทดสอบ 8 ข้อ) เพื่อให้บททดสอบไม่ซ้ำกับบทฝึก

สิ่งที่แสดงให้ผู้เรียนเห็นต่อจุดอ่อนหนึ่งจุด: อัตราผิดปัจจุบัน, คะแนนบททดสอบทุกครั้งที่ทำ (เห็นว่าดีขึ้นหรือไม่), และสถานะ (ยังไม่เริ่ม / กำลังแก้ / รอทดสอบซ้ำ / แก้ได้แล้ว)

สถานะคำนวณจาก `attempts` ที่ `source` เป็น `drill` หรือ `retest` ไม่ต้องมีตารางเพิ่ม

การตีความที่ใช้ในโค้ด:
- **ข้อ drill/retest จับคู่กับจุดอ่อนด้วย tag `weakness:*` เท่านั้น** (ไม่ใช้ skill หรือ exercise_type) เพื่อไม่ให้บททดสอบของจุดอ่อนอื่นที่ skill เดียวกันทำให้จุดอ่อนนี้ "แก้ได้แล้ว" ส่วนข้อ `lesson`/`checkpoint` จับคู่ด้วย tag เสียง/คำ, exercise_type หรือ skill ตามเดิม
- **บททดสอบต้องประกอบด้วยข้อที่ระบบตรวจให้ได้ (มี `score`)** ข้อที่ `score` เป็น null (ประเมินตัวเอง) ไม่นับ คะแนนรอบ = ค่าเฉลี่ยของ `score` ของข้อที่ตรวจได้ (นับคะแนนบางส่วน) ผ่านเมื่อค่าเฉลี่ย ≥ 0.8 (เทียบแบบรวมคะแนนเทียบ 0.8 × จำนวนข้อ เพื่อให้ 6.4 จาก 8 ผ่านพอดี) และรอบที่มีข้อตรวจได้ **น้อยกว่า 5 ข้อ ผ่านไม่ได้**
- รวมข้อเป็นรอบด้วย `session_id`; ข้อที่ไม่มี `session_id` ไม่นับ; วันของรอบคือวันตามเขตเวลาผู้ใช้ของข้อสุดท้ายในรอบ (รอบที่คร่อมเที่ยงคืนนับเป็นวันของข้อสุดท้าย)
- ยังไม่เริ่ม = ไม่มีข้อ drill/retest ในวงจรปัจจุบัน; กำลังแก้ = มีข้อแล้วแต่ยังไม่มีรอบ retest ที่ผ่าน; รอทดสอบซ้ำ = ผ่านแล้วอย่างน้อย 1 รอบ แต่ยังไม่ครบ 2 วันที่ต่างกัน (ผ่านนับสะสม ไม่ต้องติดกัน); แก้ได้แล้ว = ผ่านครบ 2 วันที่ต่างกัน
- **กลับมาอีก:** หลังแก้ได้แล้ว ไล่ดูข้อ `lesson`/`checkpoint` (ครั้งแรก มีคะแนน) ที่ทำหลังเวลาที่แก้ได้แล้ว ตามลำดับเวลา แต่ละจุดเวลาตรวจกติกาจุดอ่อน (หน้าต่าง 14 วันที่จบที่ข้อนั้น อย่างน้อย 5 ข้อ อัตราผิด ≥ 30%) ที่ข้อแรกที่เข้าเกณฑ์ จุดอ่อนกลับมา (แม้นานกว่า 14 วันแล้วก็ยังจำได้) เริ่มวงจรใหม่: เฉพาะข้อ drill/retest หลังจุดนั้นที่นับ สถานะเริ่มที่ "ยังไม่เริ่ม"
- **หายเอง:** วงจรที่เปิดอยู่ (มีข้อ drill/retest แล้ว) ปิดลง ณ ช่วงเวลาแรกที่ (ไล่ตามเวลาข้อ lesson/checkpoint และเวลาปัจจุบัน) อัตราผิดในหน้าต่าง 14 วันที่จบ ณ เวลานั้นต่ำกว่า 15% จาก ≥ 5 ข้อ นับตั้งแต่นั้น บทฝึกและบททดสอบก่อนหน้าไม่นับ ถ้าผู้เรียนกลับมาอ่อนอีก ต้องผ่านบททดสอบใหม่ 2 ครั้งในคนละวัน
- **แนะนำประจำวัน** (`recommendDrills`): เลือกจากรายการ `weakPoints()` ที่ยังไม่ "แก้ได้แล้ว" เรียงอัตราผิดมากไปน้อย (เท่ากันภายใน epsilon เรียงตามมุม แล้วตามชื่อ) ไม่เกิน 2 จุด และข้ามจุดที่ "รอทดสอบซ้ำ" ซึ่งผ่านบททดสอบไปแล้ววันนี้ (ตามวันปฏิทินของผู้ใช้) เพราะต้องรอพรุ่งนี้

## 4. ระดับ CEFR โดยประมาณ

ระดับที่แสดงคือ **ระดับสูงสุดที่ผ่านครบทั้งสองเงื่อนไข**

| ระดับ | สอบวัดผลที่ต้องผ่าน (คะแนน ≥ 70%) | คำที่รู้จริงขั้นต่ำ |
|---|---|---|
| Pre-A1 | (เริ่มต้น) | 0 |
| A1 | วันที่ 60 (จบเฟส 1) | 400 |
| A2 | วันที่ 150 (จบเฟส 2) | 1,200 |
| B1 | วันที่ 270 (จบเฟส 3) | 1,840 |
| B2 | วันที่ 360 (สอบครั้งสุดท้าย) | 2,400 |

- ผ่านสอบวัดผล = แถว `progress` ของวันนั้น `status = done` และ `score` ≥ 0.7 (`score` เป็นสัดส่วน 0–1 ไม่ใช่ 0–100, เทียบแบบมี epsilon เล็กน้อย; ค่าที่ไม่ใช่ตัวเลขจำกัดถือว่าไม่ผ่าน, ค่านอก 0–1 ถูกบีบให้อยู่ในช่วง)
- ระดับที่แสดงคือระดับสูงสุดที่ผ่านทั้งสองเงื่อนไข (ไม่ต้องผ่านระดับก่อนหน้าตามลำดับ)
- จำนวนคำขั้นต่ำคิดจาก 80% ของคำสะสมตามแผนในแต่ละเฟส (500 / 1,500 / 2,300 / 3,000 ได้ 400 / 1,200 / 1,840 / 2,400)
- แสดงความคืบหน้าไประดับถัดไปเป็นเปอร์เซ็นต์ โดยใช้ค่าที่น้อยกว่าระหว่างความคืบหน้าของคำศัพท์กับความคืบหน้าของบทเรียน
  - ความคืบหน้าคำศัพท์ = คำที่รู้จริง / จำนวนขั้นต่ำของระดับถัดไป (สูงสุด 100%)
  - ความคืบหน้าบทเรียน = จำนวนวันที่ `done` ก่อนวันสอบวัดผลของระดับถัดไป (วันสอบนับเมื่อผ่านแล้วเท่านั้น) / วันสอบวัดผลนั้น เช่น ไป A2: หารด้วย 150
  - ปัดเศษลง เพื่อให้ 100% หมายถึงผ่านจริง; ระดับ B2 ไม่มีระดับถัดไป
- ในแอปต้องเขียนกำกับว่าเป็น **"ระดับโดยประมาณ"** เพราะคำนวณจากผลในแอป ไม่ใช่ผลสอบมาตรฐาน

## 5. เรียนตามแผน 365 วัน

```
วันที่ควรอยู่   = จำนวนวันนับจาก start_date + 1        (ไม่เกิน 365)
วันที่เรียนถึง  = จำนวนบทเรียนที่สถานะ done
ช้ากว่าแผน     = วันที่ควรอยู่ − วันที่เรียนถึง − 1     (บทของวันนี้ยังไม่นับว่าช้า)
ความเร็ว       = จำนวนบทที่จบใน 14 วันล่าสุด / min(14, วันที่ควรอยู่)   (บทต่อวัน)
วันที่คาดว่าจบ  = วันนี้ + (365 − วันที่เรียนถึง) / ความเร็ว
```

| สถานะ | เงื่อนไข |
|---|---|
| ทันแผน | ช้ากว่าแผน ≤ 0 วัน |
| ช้าเล็กน้อย | ช้า 1–3 วัน |
| ช้ากว่าแผน | ช้า 4 วันขึ้นไป และแสดงจำนวนวันกับวันที่คาดว่าจะจบ |

- ความเร็วนับบทที่ `done` และ `completed_at` อยู่ใน 14 วันปฏิทินล่าสุดตามเขตเวลา (วันนี้รวมอยู่ด้วย); วันที่คาดว่าจบปัดวันขึ้นเป็นเลขเต็ม; ถ้าจบครบ 365 บทแล้ว วันที่คาดว่าจบคือวันนี้
- ผู้เรียนใหม่ที่เริ่มได้ไม่ถึง 14 วัน หารด้วยจำนวนวันที่เรียนมา (ไม่ใช่ 14) เช่น เริ่มมา 10 วัน จบ 6 บท ความเร็ว = 0.6 ไม่ใช่ 0.43; วันที่คาดว่าจบใช้ตัวหารเดียวกัน
- `start_date` ที่ไม่ใช่วันที่จริงรูปแบบ `YYYY-MM-DD` ทำให้ `estimatePace` โยน error ที่อธิบายชัดเจน (ไม่คืน NaN)
- เขตเวลาที่ไม่ถูกต้องหรือว่าง ถอยกลับเป็น `Asia/Bangkok` (หน้าตั้งค่าตรวจก่อนบันทึกด้วย `isValidTimeZone()`)
- ถ้าวัน `start_date` ยังมาไม่ถึง วันที่ควรอยู่เป็น 1
- ถ้าความเร็วเป็น 0 (ไม่ได้เรียนเลยใน 14 วัน) ให้แสดงว่า "ยังคำนวณวันจบไม่ได้" แทนการหารด้วยศูนย์
- วันที่ใช้เขตเวลาใน `profiles.timezone` (ค่าเริ่มต้น `Asia/Bangkok`) คำนวณด้วย `Intl` ในตัวเท่านั้น
- **streak:** นับวันปฏิทิน (ตามเขตเวลาผู้ใช้) ว่าเรียนแล้วเมื่อ จบบทเรียนของวันนั้น **หรือ** ทบทวนคำศัพท์ที่ถึงกำหนดในวันนั้นครบทุกใบ (ตอนนี้มีการจบบทเรียน และการเล่นบทเดิมซ้ำ **ทั้งบทจนจบ** (`activity_days.source = 'practice'`; เล่นทีละทักษะไม่นับ และต้องมี attempt ของรอบนั้นอย่างน้อย 1 รายการ วันที่ของการนับไม่ต่ำกว่าวันที่จบบทนั้นเอง จึงเติมวันย้อนหลังไม่ได้) ที่เรียก `touchStreak(tx, userId, localDate, source)` จาก `src/db/queries/progress.ts`; ส่วนทบทวนคำศัพท์จะเรียกฟังก์ชันเดียวกันใน PR SRS) วันที่มีกิจกรรมเก็บในตาราง `activity_days` และ `streaks` ถูกคำนวณใหม่จากตารางนี้ด้วย `computeStreak(dates)` ใน `src/lib/progress/streak.ts` จึงไม่ขึ้นกับลำดับที่ข้อมูลมาถึง (วันจันทร์ที่ออฟไลน์แล้วซิงก์วันพุธยังต่อเข้ากับวันอังคารได้) `current` = ช่วงวันติดกันที่จบที่วันล่าสุดที่มีกิจกรรม; การแสดงว่า "ยังไม่ขาดของวันนี้" เป็นเรื่องของหน้าจอ `longest` = ช่วงที่ยาวที่สุด
- ตัวเลขอื่นที่แสดงคู่กัน: streak ปัจจุบันและสูงสุด, เวลาฝึกรวมต่อสัปดาห์ (จาก `duration_ms`)

## 7. สิ่งที่ยังไม่ได้ออกแบบ

- **คะแนนรายทักษะย้อนหลังเป็นกราฟ:** ข้อมูลดิบพอสำหรับทำได้ แต่ยังไม่อยู่ในขอบเขตที่เลือกไว้
- **รูปแบบไฟล์ `content/drills/`:** ยังไม่ได้กำหนดใน `docs/CONTENT_SCHEMA.md` (คาดว่าใช้ exercise type เดิม เพิ่มช่อง `focus` และ `difficulty`) ต้องออกแบบก่อนเริ่มเขียนคลังบทฝึก
- **tag ของแบบฝึกหัดในไฟล์บทเรียน:** ตอนนี้หน้าเล่นบทเรียนต้องอนุมาน tag เอง (จาก `phoneme_intro` ของบทนั้นและ `vocabId`) ถ้าไม่แม่นพอ ต้องเพิ่มช่อง `focus` ใน `docs/CONTENT_SCHEMA.md`
- **เกณฑ์ทั้งหมด** (7 วัน, 21 วัน, 30%, 70%, จำนวนคำต่อระดับ) เป็นค่าตั้งต้นจากการประมาณ ต้องปรับหลังมีข้อมูลการเรียนจริง
